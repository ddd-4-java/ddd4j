# mybatis-enhance 增强计划：移植 mybatis-plus-enhance 的完整功能

## 目标

以 **mybatis-enhance**（纯 MyBatis 体系）为基础，把 mybatis-plus-enhance 的完整功能移植过来，使两个组件功能对等。同时两个组件都去掉 Spring 依赖。

## 关键决策

1. **引入 mybatis-plus 依赖** —— mybatis-enhance 父 pom 已预留 `mybatis-plus.version=3.5.9`，但当前无子模块使用。移植 InnerInterceptor 体系必须引入。
2. **保留 enhance 的 AbstractInterceptor 体系** —— i18n 的完整逻辑依赖它（MetaStatementHandler 反射链）。不替换为 MP InnerInterceptor，而是**新增** MP InnerInterceptor 实现并存的模式。
3. **两个组件都去 Spring** —— enhance 用 hutool/JDK 替换 Spring 工具类；plus-enhance 的 service 层 @Transactional/@Autowired 抽为可选。

## 分模块改造清单

### 模块 1：crypto 加解密 — 取 plus-enhance 完整实现

**删除 enhance 的半成品**（4 个文件）：
- `DecryptInterceptor.java`（空壳）
- `FieldCryptoInnerInterceptor.java`（空类）
- `InstantTypeCryptoHandler.java`（全注释）
- `EncryptInterceptor.java`（独立 Interceptor，被 plus 版替代）

**从 plus-enhance 移植**（10 个文件）：
- 注解：`EncryptedField`（标记型，无参）、`EncryptedTable`、`IgnoreEncrypted`
- SPI：`EncryptedFieldHandler`（3 方法：encrypt/decrypt/hmac）
- Handler：`DataEncryptionHandler`（接口）+ `DefaultDataEncryptionHandler`（完整实现）
- 默认实现：`DefaultEncryptedFieldHandler`（SM4/AES + HMAC）
- 拦截器：`DataEncryptionInnerInterceptor`（加密）+ `DataDecryptionInnerInterceptor`（解密）
- 工具：`SymmetricCryptoUtil`、`SymmetricAlgorithmType`（枚举）
- 辅助：`EnhanceInnerInterceptor`（标记接口）

**包路径**：保持 `org.apache.ibatis` 风格 → 改为 `org.apache.ibatis.enhance.crypto.*`

### 模块 2：sensitive 数据脱敏 — 全新移植（enhance 当前是空壳）

**从 plus-enhance 移植**（20 个文件）：
- 注解（8 个）：`SensitiveField`、`SensitiveJSONField`、`SensitiveJSONFieldKey`、`SensitiveEncryptEnabled`、`SensitiveBinded`、`SensitiveStrategy`、`SensitiveType`（枚举）、`Sensitive`（组合）
- SPI：`SensitiveTypeHandler`（接口）
- 注册表：`SensitiveTypeRegisty`
- Handler：`DataMaskingHandler`（接口）+ `DefaultDataMaskingHandler`
- 拦截器：`DataMaskingInnerInterceptor`
- 脱敏处理器（11 个）：Default/Name/IDCard/FixedPhone/MobilePhone/Address/Email/BankCard/Cnaps/PaySignNo/None
- 删除 enhance 的 `sensitive/T.java`（空壳）

### 模块 3：signature 数据签名 — 全新移植（enhance 无此能力）

**从 plus-enhance 移植**（7 个文件）：
- 注解：`TableSignature`、`TableSignatureField`
- SPI：`DataSignatureHandler`（接口）+ `DataSignatureReadWriteProvider`（接口）
- 实现：`DefaultDataSignatureHandler`、`DefaultDataSignatureReadWriteProvider`
- 拦截器：`DataSignatureInnerInterceptor`
- 依赖 crypto 的 `EncryptedFieldHandler.hmac`

### 模块 4：injector SQL 注入器 — 全新移植

**从 plus-enhance 移植**（8 个文件）：
- `EnhanceSqlInjector`（继承 DefaultSqlInjector）
- `EnhanceSqlMethod`（枚举）
- 5 个 SelectIgnoreDecrypt 方法类
- `EnhanceMapper`（接口，继承 BaseMapper）
- 依赖 mybatis-plus-extension

### 模块 5：tenant 租户隔离 — 移植并重构

**从 plus-enhance 移植**（2 个文件）：
- `TenantContext` — **重构为 ThreadLocal**（原实现用全局 ConcurrentHashMap 有并发问题）
- `PreTenantHandler` — 实现 MP 的 `TenantLineHandler`

### 模块 6：i18n 国际化 — 保留 enhance 逻辑，去 Spring

**保留** enhance 的完整 i18n 实现（19 个文件），改造：
- 修正包路径 `i18n/i18n/` → `i18n/`（去掉重复层）
- 替换 Spring 工具：
  - `AnnotationUtils.findAnnotation` → hutool `AnnotationUtil.getAnnotation` 或 MP `AnnotationUtils`
  - `DigestUtils.md5DigestAsHex` → hutool `DigestUtil.md5Hex`
  - `BeanUtils.instantiateClass` → JDK `clazz.getDeclaredConstructor().newInstance()`
  - `BeanUtils.getPropertyDescriptors` → JDK `Introspector.getBeanInfo().getPropertyDescriptors()`
  - `ObjectUtils.toObjectArray` → JDK 反射 `Array.getLength` + 手写
- 替换 `BeanMethodDefinitionFactory`（Spring Mapper 扫描缓存）→ 纯 Java 反射查找（MappedStatement.getId() = "className.methodName"，直接 `Class.forName + getMethod`）
- 删除 `org/mybatis/spring/` 整个包（4 个 Spring 集成胶水文件）
- 修复 `AbstractDataI18nColumnInterceptor` 的 `replaceAll` 返回值丢弃 bug

### 模块 7：dbperms 数据权限 — 保留 enhance 建模，去 Spring

**保留** enhance 的 dbperms 建模（6 注解 + 6 DTO + 解析器接口），改造：
- 替换 Spring 工具（同 i18n 的替换清单）
- `AbstractDataPermissionInterceptor` 的 `AnnotationUtils` → hutool
- `DefaultTablePermissionScriptHandler` 的 `CollectionUtils` → JDK `isEmpty()`

### 模块 8：service 层 — 移植 plus-enhance（可选 Spring）

**从 plus-enhance 移植**（2 个文件）：
- `IEnhanceService`（接口，~650 行 default 方法）
- `EnhanceServiceImpl`（实现）
- **保留 @Transactional/@Autowired**（这是 Spring 生态标准用法，MP ServiceImpl 本身基于 Spring）
- 单独放在 extension 的可选包中，或新建 `mybatis-enhance-spring` 子模块

### 模块 9：core 清理

**删除死代码**（4 个文件）：
- `MybatisEnhanceInterceptor.java`（空壳）
- `MetaHandler.java`（空标记接口）
- `InnerInterceptor.java`（空标记接口，与 MP 同名但无关）
- `org/mybatis/spring/` 整个包（4 个 Spring 集成胶水文件）

**替换 Spring 工具**（2 个文件）：
- `Assert.java` 的 `StringUtils.isEmpty` → commons-lang3
- `uid/Sequence.java` 的 `StringUtils.hasText` → commons-lang3

**保留**（11 个文件）：
- AbstractInterceptor + AbstractInterceptorAdapter + 4 个 Meta 反射类 + MybatisUtils + MybatisException + MapResultHandler + MetaObjectHandler

### 模块 10：pom 依赖调整

**mybatis-enhance 父 pom**：
- 新增 `mybatis-plus` + `mybatis-plus-extension` + `mybatis-plus-jsqlparser` 依赖（extension 模块）
- 删除 `spring-context` + `spring-jdbc`（core/extension 模块）
- 保留 `mybatis-spring`（optional，service 层用）

**mybatis-plus-enhance 父 pom**：
- 删除 `spring-web`（冗余）
- service 层 `@Transactional`/`@Autowired` 保留（Spring 生态标准）

## 执行顺序

1. **core 清理**：删死代码 + 去 Spring 工具（最小改动，先让 core 干净）
2. **crypto 移植**：从 plus-enhance 复制 10 个文件 + 改包名
3. **sensitive 移植**：从 plus-enhance 复制 20 个文件 + 改包名
4. **signature 移植**：从 plus-enhance 复制 7 个文件 + 改包名
5. **injector 移植**：从 plus-enhance 复制 8 个文件 + 改包名
6. **tenant 移植+重构**：复制 2 个文件 + TenantContext 改 ThreadLocal
7. **i18n 去 Spring**：替换工具 + 删 Spring 胶水 + 修包路径 + 修 bug
8. **dbperms 去 Spring**：替换工具
9. **service 移植**：复制 2 个文件（保留 Spring 注解）
10. **pom 调整 + 编译验证**

## 预期结果

- mybatis-enhance 从 116 文件（3 模块）→ 约 180 文件（3 模块），功能与 plus-enhance 对等
- 两个组件都零 Spring 依赖（service 层除外）
- crypto/sensitive/signature/injector/tenant 从 plus-enhance 完整移植
- i18n/dbperms 保留 enhance 原有逻辑，去 Spring 后独立可用
