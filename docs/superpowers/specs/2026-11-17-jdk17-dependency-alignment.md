# 2.0.x 公开依赖修复与一致性门禁

状态：实施中。范围为 feature/2.0.x，延续仓库现有规格体系及三线兼容约定。

## 约束与验收

- 保持 JDK 17、Spring Framework 6、Security 6、Boot 3、Data JPA 3，以及项目版本 2.0.x.20260630-SNAPSHOT。
- 保留已有未提交依赖更新；仅修改依赖管理、受影响测试、CI 和本变更文档，不改变业务逻辑、认证策略或持久化契约。
- 第三方版本由 ddd4j-dependencies 集中定义。升级公开稳定版本，验证实际制品基础字节码不超过 Java 17。
- 修复平台 BOM 覆盖：中央及子模块的 Reactor、ASM、Jackson 等管理结果与共享属性一致。
- Netty 4.2 为默认线；Quarkus、Helidon 3、Micronaut 4 使用集中定义的 Netty 4.1 兼容线。同一模块实际依赖不得混用两线或不同补丁。tcnative 等独立版本体系按各自 BOM 验证。
- Quarkus 保持其 Vert.x 4 平台线，独立 Vert.x 适配使用 Vert.x 5；两线分别在中央定义补丁版本。
- CI 在 JDK 17 下检查全部 reactor 有效模型、完整实际依赖树及受影响回归；缺失、重复、失败、过期输入必须失败，不能静默跳过。
- 保留原三线 Spring 检查，不修改 1.0.x、3.0.x 的分支内容。
- 扫描解析依赖及管理目录，结合厂商公告报告遗留漏洞、公开修复可用性及触发条件。不能把单一数据库零命中称为安全清零，不新增抑制规则。
- 测试、字节码、扫描、CI 配置和远端 CI 分别记录。环境导致无法完成的容器验收保留失败或未完成状态。

## 执行顺序

1. 固定基线，先添加可捕获已发现混版和覆盖问题的检查器回归。
2. 增补检查器，在当前模型/依赖树上取得真实红灯。
3. 更新中央公开版本与 BOM 优先级，增补必要的平台模块兼容覆盖。
4. 运行全部有效模型及解析树门禁，再执行 JDK 17 回归与字节码检查。
5. 扫描并更新遗留漏洞清单，复核 CI 和源码差异。

未包含提交、推送、发布或部署；本次交付为当前分支可审查修改及本地验证证据。
