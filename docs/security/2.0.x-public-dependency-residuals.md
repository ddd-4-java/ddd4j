# 2.0.x 公开版本遗留漏洞

本轮保留 JDK 17 / Spring 6。以下依据 2026-11-17 已保存的 OSV 扫描快照和 Spring 官方公告。
**最后一轮配置收敛后尚未完成回归与重新扫描，不能把此快照当成当前工作区的安全清零证明。**

2026-11-18 后续清理已从中央源码移除 32 个未使用的旧管理声明（包括旧 CXF、Derby、Hystrix、旧异步 HTTP 等），并补齐 CXF / WSS4J 公开配套补丁。完整退出范围及 CI 规则见 [退出记录](../dependency-retirement-jdk17.md)。这属于源码变更证据；没有重新扫描，因此不删除下方历史告警或将其改记为扫描已修复。上游 BOM 仍可能带有未使用的旧管理元数据，CI 会单列并保留其扫描输入。

完整坐标、版本、CVE/GHSA、同坐标修复区间、处理原因及来源见 [CSV 清单](2.0.x-public-dependency-residuals.csv)。
`actual-in-snapshot` 表示当时的模块解析依赖；`managed-only-in-snapshot` 表示仅存在于管理目录，不代表默认应用已加载。

## 2026-11-17 截图问题的后续处理

验收目标为实际解析依赖只保留 Spring 6 生态缺少公开兼容修复版的公告。以下是当前源码已配置的修复，**没有运行新的 Maven 构建、测试、有效模型生成或全仓漏洞扫描，均未取得最终验收证据**。截图未包含各条告警的 CVE/GHSA 标识，不能将“升级到更新版本”直接等同于该告警已消失。

| 组件 | 截图版本 | 当前源码处理 |
|---|---|---|
| Logback Classic / Core | 1.5.38 | 同步升级至 1.6.7，补充 Dropwizard 默认访问日志兼容工厂；不再以日志兼容为由永久保留 1.5。 |
| BC LTS Provider | 2.73.12.1 | NATS 排除旧传递依赖，显式选择 2.73.13；LTS Provider / Util / PKIX 在中央统一管理。 |
| JAXB Runtime | 2.3.9 | 保留用户已配置的 4.0.9，并直接管理 Runtime / Core / TXW2；Excel 排除默认 Ehcache，显式使用同版 Jakarta 变体和 JAXB 4。 |
| JSON Smart | 2.6.0 | JSON Smart 与 Accessors Smart 同步选择 2.6.1。 |
| Shiro | 2.2.1 | 保留用户已配置的 3.0.2，补齐 Lang / Config / Cipher / Event 家族管理；未修改 Realm 或降低认证要求，凭据兼容回归仍待执行。 |
| Android JSON | 0.0.20131108.vaadin1 | 四个 Boot 测试入口排除该依赖，并显式引入中央管理的 org.json:json:20260814；JSONassert 保持公开稳定版 1.5.3。 |
| Zstd JNI | 1.5.7-11 | 中央统一升级至 1.5.7-28，覆盖 Kafka / RocketMQ 等传递引入。 |
| Micrometer | Registry 1.7.2 / Core 1.10.4 | 2026-11-18：指标库统一为 1.17.2，Tracing 独立为 1.7.2；两个 BOM 移到 Hibernate 等平台之前，CI 同时检查中央表和实际依赖，不再接受中央自身的混版。 |

官方依据：[Logback 1.6.7 及安全修复记录](https://logback.qos.ch/news.html)、[BC LTS 2.73.13 发布](https://www.bouncycastle.org/resources/new-release-bouncy-castle-java-lts-2-73-13/)、[JSON Smart 2.6.1 修复 CVE-2026-113602](https://github.com/netplex/json-smart-v2/blob/master/README.md)、[Shiro CVE-2026-56130 公告](https://github.com/advisories/GHSA-m8g6-vrr2-x7ff)。Zstd 版本以 [Maven Central 发布元数据](https://repo.maven.apache.org/maven2/com/github/luben/zstd-jni/maven-metadata.xml)为准。

CI 新增这些组件的中央安全基线、解析版本和旧 JSON / javax Ehcache 回流检查。已有 CSV 保留原扫描快照，不将其中 Shiro 2.2.1 的旧记录冒充本轮新扫描结果，也不提前标记为修复通过。管理目录历史保留项仍见下文，不能因为截图项已更新就宣称管理目录已清零。

Micrometer 的 [CVE-2026-40984](https://spring.io/security/cve-2026-40984/) 已有公开修复，不属于 Spring 6 企业渠道限制。当前修复的版本依据为 [Micrometer 1.17.2](https://github.com/micrometer-metrics/micrometer/releases/tag/v1.17.2) 和 [Tracing 1.7.2](https://github.com/micrometer-metrics/tracing/releases/tag/v1.7.2)，未重新运行解析或扫描，当前状态仍为配置待验收。

|---|---|---|

| [CVE-2026-47842](https://spring.io/security/cve-2026-47842/) | Security Crypto 6.5.11；6.5.12 企业渠道 | AES/CBC 固定 IV；确有使用时还需兼容旧密文，不能直接换算法。 |
| [CVE-2026-47834](https://spring.io/security/cve-2026-47834/) | Data JPA 3.5.13；3.5.14 企业渠道 | 不可信排序进入带 Sort/Pageable 的原生 SQL 方法；消费方采用字段/方向白名单。 |

用户已确认没有 Spring 企业仓库，按公开版本交付。不会把 Spring 7 / Security 7 / Data JPA 4 放进本分支以消除告警。
本仓相关 Java 源码的定向检索没有发现上述 SpEL、AES 和 NativeQuery 危险组合的直接用法；这不能证明第三方内部或下游应用不存在利用路径。

## 管理目录中的其他保留项

- 停止维护或需要换坐标/API：bcprov-jdk15on、Commons Configuration 1、HttpClient 3、Commons Lang 2、旧 MySQL 驱动坐标、旧 Querydsl 坐标、not-yet-commons-ssl。
- 受 JDK 或框架平台约束：Derby、Hibernate Reactive、MCP 0.x。公开修复涉及升级 JDK、ORM 平台或 SDK 主版本，不能称为本轮已修复。
- 预发布集成线：LangChain4j MariaDB / PGVector；公告修复位于 beta 线，本轮没有新增预发布升级候选。
- 公告库未列修复发行版或区间：jsonschema2pojo-core、resteasy-netty4-cdi、Undertow；需要上游确认或消费方迁移。

以上是“本轮未修复”的具体分类，不等同于全部没有公开修复方案。没有添加漏洞忽略规则或降低现有周更扫描阈值。
