# 3.0.0 迁移指南：Publisher 静态注册 → 上下文查找

> **破坏性变更**：3.0.0 起，`DomainEvent.registerPublisher()` 与 `MQEvent.registerPublisher()` **已删除**，业务方不再需要在启动时手动注册 SPI 实现。
>
> 改为由**框架适配层在启动期**自动注入，业务代码**完全无感**。

---

## 一、为什么改变？

### 1.1 旧实现的问题

```java
// 2.x 旧实现（已删除）
public abstract class DomainEvent<T> {
    private static volatile DomainEventPublisher eventPublisher;  // ❌ 进程级单点

    public static void registerPublisher(DomainEventPublisher publisher) {
        eventPublisher = publisher;  // ❌ 谁来调？什么时候调？
    }
}

// 业务代码被迫
public class MyApp {
    public static void main(String[] args) {
        // ❌ 业务代码必须知道这个钩子
        DomainEvent.registerPublisher(springPublisher);
        MQEvent.registerPublisher(kafkaPublisher);

        SpringApplication.run(MyApp.class, args);  // 顺序还得对
    }
}
```

**五大问题**：

| # | 问题 | 后果 |
|---|------|------|
| 1 | 生命周期错配 | 业务 `new MQEvent()` 时 publisher 可能未注入 |
| 2 | 多租户隔离失效 | 静态变量全局共享，多租户场景无法隔离 |
| 3 | 单测灾难 | 无法在测试中替换 publisher |
| 4 | 静态可变状态 | 违反 ddd4j "零静态可变状态"原则 |
| 5 | 耦合框架 | 业务代码必须知道 registerPublisher 这个钩子 |

### 1.2 新实现的优势

```java
// 3.0.0 新实现
public abstract class DomainEvent<T> {
    public <R> R publish() {
        // 自动从上下文查找（线程优先 → 全局兜底）
        DomainEventPublisher publisher = Contexts.injectOrThrow(
                SpiKeys.DOMAIN_EVENT_PUBLISHER, DomainEventPublisher.class);
        publisher.publish(this);
        return (R) result;
    }
}

// 业务代码
public class MyApp {
    public static void main(String[] args) {
        // ✅ 业务代码完全无感
        SpringApplication.run(MyApp.class, args);
        // 框架适配层自动注入 SPI 到上下文
    }
}
```

**五大优势**：

| # | 优势 | 体现 |
|---|------|------|
| 1 | 生命周期解耦 | 业务 `new MQEvent()` 时无需关心 publisher 是否就绪 |
| 2 | 多租户隔离 | 线程级 publisher 可覆盖全局默认（多租户不同 MQ 集群） |
| 3 | 测试友好 | 单测时直接 `Contexts.register(KEY, mockImpl)` |
| 4 | 零静态可变状态 | 符合 ddd4j 框架无关纯净契约理念 |
| 5 | 零框架耦合 | 业务代码完全不知道 Spring / Quarkus / Guice 的存在 |

## 二、迁移步骤

### 2.1 删除旧代码

```java
// ❌ 删除
DomainEvent.registerPublisher(myPublisher);
MQEvent.registerPublisher(myPublisher);

// ❌ 删除
DomainEvent.getPublisher();  // 已不存在
MQEvent.getPublisher();      // 已不存在
```

### 2.2 添加框架适配层依赖（必须）

```xml
<!-- Spring Boot 业务项目 -->
<dependency>
    <groupId>io.ddd4j</groupId>
    <artifactId>ddd4j-runtime-spring</artifactId>
</dependency>

<!-- Quarkus 业务项目 -->
<dependency>
    <groupId>io.ddd4j</groupId>
    <artifactId>ddd4j-runtime-quarkus</artifactId>
</dependency>

<!-- Guice 业务项目 -->
<dependency>
    <groupId>io.ddd4j</groupId>
    <artifactId>ddd4j-runtime-guice</artifactId>
</dependency>
```

### 2.3 提供 SPI 实现（仅需标准 Bean 声明）

业务方只需按 SPI 接口声明 Bean，无需任何额外配置：

```java
// Spring 示例
@Component
public class MyDomainEventPublisher implements DomainEventPublisher {
    @Override
    public void publish(DomainEvent event) {
        applicationEventPublisher.publishEvent(event);
    }
}

// Quarkus 示例
@ApplicationScoped
public class CdiDomainEventPublisher implements DomainEventPublisher {
    @Inject Event<Object> event;
    @Override
    public void publish(DomainEvent domainEvent) {
        event.fire(domainEvent);
    }
}

// MQ Event Publisher（可选）
@Component
public class KafkaMQEventPublisher implements MQEventPublisher {
    @Autowired KafkaTemplate<String, String> kafkaTemplate;
    @Override
    public <T extends MQEvent> void publish(T event, MQDestination destination) {
        // 序列化 + 发送到 Kafka
    }
}
```

**框架适配层会自动**：
- 启动期扫描这些 Bean
- 注入到 ddd4j 上下文（`BaseContext`）
- 业务代码无感使用

### 2.4 单元测试场景

```java
@Test
void testPublish() {
    // 单测时直接注入 mock（无需 Spring 上下文）
    DomainEventPublisher mockPublisher = mock(DomainEventPublisher.class);
    BaseContext.inject(SpiKeys.DOMAIN_EVENT_PUBLISHER, DomainEventPublisher.class, mockPublisher);

    try {
        new OrderCreatedEvent(orderId).publish();
        verify(mockPublisher).publish(any());
    } finally {
        // 测试隔离
        BaseContext.remove(SpiKeys.DOMAIN_EVENT_PUBLISHER);
    }
}
```

或用 `try-with-resources` 模式：

```java
@Test
void testPublishWithAutoCleanup() {
    DomainEventPublisher mockPublisher = mock(DomainEventPublisher.class);
    try (ContextScope ignored = Contexts.scope(DOMAIN_EVENT_PUBLISHER, mockPublisher)) {
        new OrderCreatedEvent(orderId).publish();
        verify(mockPublisher).publish(any());
    }
    // 自动清理 BaseContext 中的 mock
}
```

## 三、API 速查

### 3.1 业务方使用（不变）

```java
// ✅ 业务代码无需任何改动
new OrderCreatedEvent(orderId, amount)
    .publish();  // 3.0.0+ 自动从 Contexts 查找 publisher

new OrderPaidEvent(orderId)
    .publishIn(5000);  // 5秒后延迟发布

new MQOrderEvent(orderId)
    .topic("order-events")
    .publish();  // 自动从 Contexts 查找 MQ publisher
```

### 3.2 框架适配层注入

```java
// 启动期注入（类型安全版本，框架适配层已自动处理）
BaseContext.inject(SpiKeys.DOMAIN_EVENT_PUBLISHER, DomainEventPublisher.class, myImpl);
BaseContext.inject(SpiKeys.MQ_EVENT_PUBLISHER, MQEventPublisher.class, myImpl);
```

### 3.3 SPI 约定 key

| Key 常量 | 对应类型 |
|---------|---------|
| `SpiKeys.DOMAIN_EVENT_PUBLISHER` | `DomainEventPublisher` |
| `SpiKeys.MQ_EVENT_PUBLISHER` | `MQEventPublisher` |
| `SpiKeys.SUBJECT_PROVIDER` | `SubjectProvider` |
| `SpiKeys.I18N_PROVIDER` | `I18nProvider` |

### 3.4 上下文查找策略

```
Contexts.inject(KEY, Class)        ← 门面（线程优先 → 全局兜底）
   ↓
ThreadContext.inject(KEY, Class)   ← 请求级（覆盖全局）
   ↓ 命中即返回
BaseContext.inject(KEY, Class)     ← JVM 级（全局默认）
   ↓ 都未命中 → Optional.empty()

未找到想抛异常？
Contexts.injectOrThrow(KEY, Class)  ← 一步到位
```

## 四、多租户场景示例

```java
// 拦截器：为当前线程注入租户专属的 MQEventPublisher
@Component
public class TenantInterceptor implements HandlerInterceptor {

    @Autowired
    private Map<String, MQEventPublisher> tenantPublishers;  // tenant_1 → KafkaA, tenant_2 → KafkaB

    @Override
    public boolean preHandle(HttpServletRequest req, HttpServletResponse resp, Object handler) {
        String tenantId = req.getHeader("tenant-id");
        MQEventPublisher publisher = tenantPublishers.get(tenantId);

        // 线程级注入（仅当前请求有效）
        ThreadContext.inject(SpiKeys.MQ_EVENT_PUBLISHER, MQEventPublisher.class, publisher);

        return true;
    }

    @Override
    public void afterCompletion(HttpServletRequest req, HttpServletResponse resp, Object handler, Exception ex) {
        // 请求结束自动清理（ThreadContext 基于 TransmittableThreadLocal）
        ThreadContext.remove(SpiKeys.MQ_EVENT_PUBLISHER);
    }
}
```

## 五、常见问题

### Q1: 业务项目必须升级到 3.0.0 吗？

**A**: 不强制。3.0.0 之前版本继续可用。但建议升级以获得更好的可测试性和多租户支持。

### Q2: 升级后会破坏现有代码吗？

**A**: 是的，会编译失败。删除所有 `DomainEvent.registerPublisher()` / `MQEvent.registerPublisher()` 调用即可。

### Q3: 能否在 3.0.0 中临时保留旧 API？

**A**: 不行。本变更已硬切换（`@Deprecated` 都不留），确保业务方必须迁移到正确的上下文机制。

### Q4: 性能影响？

**A**: 微乎其微。`Contexts.inject()` 内部走 `ConcurrentHashMap.get()`，O(1) 时间复杂度，与旧的静态变量访问相当。

### Q5: 如何实现请求级覆盖？

**A**: 使用 `ThreadContext.inject(KEY, TYPE, impl)` 注入线程级 publisher，业务方法调用 `publish()` 时自动优先使用线程级。
