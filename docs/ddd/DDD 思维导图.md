# DDD（领域驱动设计）思维导图

## 📌 **核心概念层级**

```
├── 战略设计
│   ├── 限界上下文 (Bounded Context)
│   ├── 上下文映射图
│   │   ├── 合作关系
│   │   ├── 共享内核
│   │   ├── 客户-供应商
│   │   ├── 遵奉者
│   │   ├── 防腐层
│   │   ├── 开放主机服务
│   │   └── 发布语言
│   ├── 子域划分
│   │   ├── 核心域
│   │   ├── 支撑子域
│   │   └── 通用子域
│   └── 统一语言
│       ├── 术语表
│       └── 上下文含义
```

## 🔧 **战术设计（领域层）**

```
├── 实体 (Entity)
│   ├── 唯一标识
│   ├── 生命周期连续性
│   └── 业务行为
├── 值对象 (Value Object)
│   ├── 不可变性
│   ├── 无标识
│   └── 描述性属性
├── 聚合 (Aggregate)
│   ├── 聚合根
│   ├── 一致性边界
│   └── 事务边界
├── 领域服务 (Domain Service)
│   ├── 无状态操作
│   └── 跨多个实体的业务逻辑
├── 领域事件 (Domain Event)
│   ├── 过去时命名
│   ├── 事件发布
│   └── 事件处理
└── 工厂 (Factory)
    ├── 复杂对象创建
    └── 封装创建逻辑
```

## 🏗️ **架构模式**

```
├── 分层架构
│   ├── 用户界面层
│   ├── 应用层
│   │   ├── 用例协调
│   │   └── 事务管理
│   ├── 领域层（核心）
│   │   ├── 实体
│   │   ├── 值对象
│   │   └── 领域服务
│   └── 基础设施层
│       ├── 持久化
│       └── 外部服务
├── 六边形架构（端口适配器）
│   ├── 内部：领域+应用
│   ├── 端口：接口定义
│   └── 适配器：实现
├── 整洁架构
│   ├── 依赖规则：外圈依赖内圈
│   └── 实体在最内层
└── CQRS（命令查询职责分离）
    ├── 命令侧：写操作
    │   ├── 领域模型
    │   └── 事件溯源（可选）
    └── 查询侧：读操作
        ├── 读模型
        └── 物化视图
```

## 📊 **设计过程与方法**

```
├── 事件风暴 (Event Storming)
│   ├── 橙色贴纸：领域事件
│   ├── 蓝色贴纸：命令
│   ├── 黄色贴纸：聚合
│   ├── 粉色贴纸：角色
│   └── 紫色贴纸：策略
├── 领域建模步骤
│   ├── 1. 发现领域概念
│   ├── 2. 识别实体和值对象
│   ├── 3. 定义聚合和聚合根
│   ├── 4. 划分限界上下文
│   └── 5. 建立上下文映射
└── 重构到深层模型
    ├── 持续重构
    ├── 突破性重构
    └── 模型精化
```

## 📈 **DDD优势与适用场景**

```
├── 适用场景
│   ├── 复杂业务领域
│   ├── 长生命周期系统
│   ├── 团队规模较大
│   └── 需要业务创新
├── 不适用场景
│   ├── 简单CRUD应用
│   ├── 技术验证项目
│   └── 短周期项目
└── 核心价值
    ├── 统一业务技术语言
    ├── 应对复杂性
    ├── 系统可维护性
    └── 业务灵活性
```

## 🎯 **关键成功因素**

1. **领域专家深度参与**
2. **团队对DDD的理解和认同**
3. **持续重构的勇气**
4. **合适的项目复杂度**
5. **良好的技术实现支撑**
